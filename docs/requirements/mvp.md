# GA-1 — требования и границы MVP GameAnalytics

Рабочая версия от 21.10.2026, обновлена по GA-3 (b5b7492). Автор: Алимов Амир Сакенулы, группа SE-2431.
Задача: [GA-1](https://gameanalytics-se2431.youtrack.cloud/issue/GA-1).
Статус: доработка требований; продуктовые правила подтверждены Амиром, идентификация CS2 остаётся открытым вопросом. Согласование команды и руководителя, реализация и прохождение приёмочных тестов этим документом не заявляются.

## 1. Назначение и охват

Платформа объединяет доступную публичную статистику CS2/Dota 2 и персональный анализ собственных записей матчей. Пользователи — игроки, тренеры и аналитики команд. Итоговый MVP включает CS2 FACEIT, CS2 Premier и Dota 2. Первая сдача 24 октября — проектные материалы, а не готовое приложение.

Гость ищет игрока по SteamID64, открывает профиль и доступные карточки матчей. Авторизованный пользователь подтверждает владение Steam-аккаунтом и загружает запись своего матча только из существующей карточки. После проверки получает асинхронный отчёт по эпизодам. Отдельной кнопки «Добавить матч» нет. Подключение истории Premier с кодами доступа и ручная загрузка демки — разные операции; автоскачивание не требуется.

Публичный просмотр означает доступ к уже имеющимся данным; полная история любого SteamID не обещается. Пустая выдача, неподключённый источник и ошибка внешнего API показываются раздельно. Персональные отчёты и файлы не становятся публичными вместе с общей статистикой.

## 4. Функциональные требования

Must — обязательно для приёмки целевого MVP; Should — улучшение. Неподтверждённая интеграция остаётся риском реализации Must, а не автоматически исключённой функцией.

| ID | Приоритет | Требование и проверяемый критерий |
|---|---|---|
| FR-01 | Must | Гость по SteamID64 открывает доступный профиль без входа; отсутствие данных и ошибка источника различимы, значения не выдумываются |
| FR-02 | Must | Единый профиль содержит отдельные блоки CS2/Dota 2, источник, период и размер выборки; отсутствующие значения — null/«нет данных», а не 0 |
| FR-03 | Must | FACEIT, Premier и OpenDota дают карточки с устойчивым внешним ID и составом, когда данные доступны; повторный импорт не создаёт дубль по (source, game, external_match_id). Premier проверяется в GA-58 |
| FR-04 | Must | Владение аккаунтом подтверждается сервером через вход Steam; ручного ввода SteamID или наличия файла недостаточно. Гость и другой владелец не выполняют защищённые операции |
| FR-05 | Must | Загрузка доступна только в существующей карточке своего матча после подтверждения аккаунта; есть инструкция, где получить запись, и объяснение недоступности. Общего экрана создания матча загрузкой нет |
| FR-06 | Must | До анализа сервер сверяет игру, поддерживаемый формат, матч и участие владельца по правилам раздела 5. Чужая, повреждённая, неоднозначная или другая запись не списывает квоту |
| FR-07 | Must | Видны стадии загрузки, проверки, очереди, обработки, успеха и ошибки; у ошибки есть причина и допустимый следующий шаг. Отчёт без найденных эпизодов считается успешно завершённым |
| FR-08 | Must | Повтор запроса/события не создаёт второе логическое задание, отчёт или списание. Повтор того же успешного анализа возвращает готовый результат; новую версию анализа пользователь запускает явно |
| FR-09 | Must | Публичные игровые показатели сверяются с эталонными событиями; показатели разных игр не объединяются в необоснованный универсальный рейтинг |
| FR-10 | Must | Личный отчёт содержит тип ошибки, время/интервал, объяснение по наблюдаемым данным и версию модели; отсутствие эпизодов не объявляется доказательством идеальной игры |
| FR-11 | Must | Free: 3 успешных анализа в месяц; Premium: без месячного лимита, но с теми же ограничениями файла и параллелизма. Отказы/ошибки не списываются; правила периода и резерва — раздел 6 |
| FR-12 | Must | Исходный файл и личный отчёт доступны только владельцу; подбор ID и чужая сессия дают отказ. Публичная базовая статистика обслуживается отдельным контрактом |
| FR-13 | Must | Пользователь видит дату удаления исходника. После истечения срока файл становится недоступен и удаляется, статистика и готовый отчёт сохраняются. Повторный анализ без файла требует повторной загрузки в ту же карточку |
| FR-14 | Should | Интерфейс обновляет статус без ручной перезагрузки и без создания нового задания; polling/SSE выбираются в реализации |

## 5. Валидация и идентификация файла

1. Сервер связывает запрос с выбранной карточкой и подтверждённым аккаунтом; клиентские заявления об ID не считаются доказательством.
2. Проверяются потоковый размер, сигнатура контейнера и поддержка парсером. Нулевой файл, неизвестный формат, повреждение, превышение любого бюджета дают отказ. Распаковка ограничена по выходным байтам независимо от заявленного размера.
3. Dota 2: извлечённый match_id должен точно совпасть с ID карточки. SteamID владельца должен присутствовать и в записи, и в доступном составе карточки. Сопоставление account_id выполняется целочисленно; SteamID64 передаётся строкой. При неизвестном/анонимном составе подтверждение не подменяется догадкой.
4. CS2: извлечение полного состава подтверждено отчётом на трёх файлах; сравниваются все 10 SteamID, участие владельца и доступные признаки карточки. Несовпадение даёт отказ. Совпадение состава и карты само по себе не доказывает идентичность: те же команды могут сыграть повторно на той же карте. Имя файла, ник, близкая длительность и один игрок также недостаточны. Для положительного допуска нужен проверенный способ привязки содержимого к конкретному матчу; до его проверки результат — «соответствие не подтверждено», без анализа и списания. Ручная проверка оператором не добавляется в MVP как обход. Это не снимает обязательство реализовать CS2 в MVP.
5. Дополнительный .dem.info, если потребуется, также валидируется и связывается с записью; произвольному sidecar-файлу нельзя доверять как независимому доказательству. Метод подлежит экспериментальной проверке, не объявлен готовым.
6. SHA-256 используется для повторной загрузки байтов, но не доказывает принадлежность матчу и не защищает от намеренной подделки метаданных. Проверка согласованности не является античитом или криптографической аттестацией Valve.

Планируемый вход MVP: несжатый Source 2 .dem и один поток zstd с распакованным Source 2 demo. Суффиксы .dem.zst/.dem.bz2 допускаются только при поддерживаемой фактической сигнатуре. Настоящий bzip2 не объявляется поддержанным по двум zstd-примерам: до отдельного теста дать инструкцию загрузить распакованный .dem. ZIP, многотомные и вложенные архивы не входят в MVP.

## 6. Квоты, хранение и ресурсные пределы

Приняты Амиром в обсуждении 21.10.2026: 3 успешных анализа за календарный месяц UTC без переноса остатка; отсутствие списания за ошибки/несоответствие; Premium без месячного лимита; одно незавершённое задание на пользователя для обоих тарифов; резервирование попытки при запуске с окончательным списанием только после успеха и освобождением при ошибке; хранение исходника 30 суток с сохранением отчёта и статистики отдельно. Детали реализации резерва и удаления заданы ниже. Это подтверждение продуктовых правил, а не согласование всего ТЗ командой и руководителем. Ресурсные бюджеты остаются предварительными: замеры не выявили превышения на пяти файлах, но не проверяли предельную нагрузку.

| Параметр | Правило версии для ревью | Основание / проверка |
|---|---|---|
| Период | Календарный месяц UTC, без переноса остатка | Подтверждено Амиром 21.10.2026 |
| Учёт | Не более 3 успешных + зарезервированных анализов в периоде Free | Атомарная проверка при принятии задания; тест конкурентных запросов |
| Граница месяца | Резерв относится к месяцу принятия задания, даже если отчёт готов в следующем | Декабрь→январь не создаёт двойное списание; ошибка освобождает исходный резерв |
| Параллелизм пользователя | 1 незавершённое задание от принятия загрузки до конечного статуса, Free и Premium | Второй независимый запрос отклоняется; повтор того же idempotency key возвращает первое задание |
| Исходная демка | 30 суток от успешного окончания загрузки, одинаково для тарифов | Срок подтверждён Амиром 21.10.2026; UI показывает expires_at |
| Удаление | С expires_at выдача файла запрещена; физическое удаление в течение 24 часов | Проверка часов и задания удаления; исходники не включаются в долгосрочные резервные копии, старые версии объекта тоже удаляются |
| Отчёт и статистика | Истечение срока демки не удаляет готовые результаты; личный отчёт можно удалить владельцу | Отдельные права и жизненный цикл, удаление демки не меняет публичные агрегаты автоматически |
| Временные файлы | Распакованные/отклонённые/незавершённые загрузки удаляются не позднее 24 часов после завершения/истечения задания | Отказ не означает хранение чужой записи 30 дней |
| Входной файл | Не более 1 GiB (1 073 741 824 байта) | Проектный лимит, не максимум из GA-3; проверять поток, не только Content-Length |
| Распакованный поток | Не более 2 GiB (2 147 483 648 байт), один уровень распаковки | Тест сжатого потока с превышением выходного объёма; коэффициент сжатия не заменяет абсолютный предел |
| Парсер на стенде | 1 процесс на worker, максимум 2 GiB RAM и 15 минут на распаковку + разбор | На выборке превышение не наблюдалось; нужны испытания под жёстким лимитом. OOM/timeout дают ошибку без списания. Это не обещание полного ML-анализа за 15 минут |
| Временный диск | Не менее 4 GiB свободного места на активный worker | Перед началом обработки; при нехватке ресурса задание не запускается |

Фактические ресурсные бюджеты подтверждаются или меняются документированным решением после benchmark GA-3/GA-27/GA-41 до включения загрузки на стенде. Изменение лимитов показывается в UI; скрытое превышение бюджета не допускается. Premium без месячной квоты не означает бесконечную вычислительную ёмкость.

## 7. Нефункциональные требования

Это цели приёмки, не результаты измерений. В протоколе фиксируются CPU/RAM/диск, версии контейнеров и парсеров, контрольные суммы набора, параметры нагрузки. Очередь, сеть, распаковка, полный парсинг и ML измеряются отдельно.

| ID | Цель | Критерий |
|---|---|---|
| NFR-01 | Быстрое чтение | p95 закэшированного профиля/карточки ≤ 1 с, ошибки сервера < 1% при 20 одновременных клиентах в течение 5 минут; внешние API измеряются отдельно |
| NFR-02 | Восстановление | Из 20 заданий после остановки одного worker все получают конечный статус в пределах настроенных таймаутов/повторов; нет потерянных заданий, дублей отчёта и списаний |
| NFR-03 | Контроль доступа | Для каждого защищённого API тест без сессии и с чужой сессией даёт отказ; приватные файлы не открываются анонимно; секреты отсутствуют в логах |
| NFR-04 | Изоляция ресурсов | Превышение каждого лимита раздела 6 останавливает только соответствующее задание; следующая допустимая запись обрабатывается |
| NFR-05 | Наблюдаемость | По job_id прослеживаются стадии во всех участвующих сервисах; доступны глубина очереди, длительность и ошибки; исходные демки и коды доступа не логируются |
| NFR-06 | Воспроизводимость | Другой участник разворачивает пять сервисов и инфраструктуру Kubernetes по инструкции, применяет миграции и проходит основной сценарий; API описан OpenAPI |
| NFR-07 | Оценка ML | Для каждой игры и согласованного типа ошибки опубликованы precision/recall/F1, baseline, число эпизодов и правило временного совпадения; разбиение по матчам без утечки. Типы ошибок и пороги до финальной оценки фиксируются в GA-52, а не выбираются по тестовому результату |

## 9. Зависимости, риски и завершение GA-1

| Вопрос | Ответственный и задача | Условие снятия |

Незавершённая реализация парсера не мешает ревью требований: требования должны описывать необходимое поведение и доказательства приёмки. Она мешает объявлять соответствующую функцию реализованной. Для закрытия GA-1 требуется принятие документа командой и руководителем; сейчас такое согласование не заявляется.

Вне обязательного MVP: автоскачивание демок, реальные платежи, matchmaking, новые игры, полная история любого Premier-игрока, публичная выдача чужих файлов и личных отчётов, универсальный межигровой рейтинг. Исходные разделы 2–4 обоснования академической готовности не изменяются.

Материалы GA-2 и GA-3 указаны по фиксированным коммитам, поскольку PR #1 и #3 ещё не в main. Этот PR содержит только GA-1 и не переносит файлы, интервью или коммиты других задач.
