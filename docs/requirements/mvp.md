# GA-1 — требования и границы MVP

Автор: Алимов Амир Сакенулы, SE-2431. Дата: 19.10.2026.
Статус: начальный проект для согласования до 21 октября; требования не утверждены.
Задача: https://gameanalytics-se2431.youtrack.cloud/issue/GA-1

## Назначение и границы

GameAnalytics объединяет доступную публичную статистику CS2/Dota 2 и анализ собственных записей матчей. Требования относятся к итоговому MVP; первая сдача 24 октября — комплект проектных материалов, а не готовое приложение.

Ровно пять прикладных сервисов: пользователи/профили; матчи/загрузки; обработка данных; статистика; обнаружение ошибок. Gateway и инфраструктура в счёт не входят. Ответственные и архитектурные границы приведены в [proposal](../proposal/project-proposal.md).

Приоритет Must означает обязательность для принятого охвата источников; Should — улучшение, допускающее перенос по согласованию. Premier обязателен независимо от текущего статуса проверки; реализация и приёмка зависят от GA-58. Поддержка анализа демки зависит от проверки GA-3. Открытые решения ниже не являются принятыми требованиями.

## Функциональные требования

| ID | Приоритет | Требование | Критерий приёмки |
|---|---|---|---|
| FR-01 | Must | Просмотр публичного профиля другого игрока без входа | Гость находит тестовый профиль по поддержанному идентификатору, видит доступные показатели; для недоступного профиля получает объяснение, а не выдуманные данные |
| FR-02 | Must | Единый профиль с разделением игр | На странице отдельно представлены CS2/Dota 2, источник, период и размер выборки; отсутствие данных не становится нулём |
| FR-03 | Must | История и карточки поддержанных матчей | На согласованных примерах GA-2 карточка содержит внешний ID, источник и доступные поля; повторный импорт не создаёт дубль |
| FR-04 | Must | Подтверждение владения игровым аккаунтом | Нельзя подтвердить аккаунт вводом чужого SteamID; защищённые действия требуют проверенной сессии |
| FR-05 | Must | Загрузка только из существующей карточки своего матча | В карточке есть кнопка и инструкция получения записи; общего создания матча загрузкой нет; пользователь без подтверждения/участия получает отказ |
| FR-06 | Must | Проверка записи до анализа | Правильная тестовая запись принимается; запись другого матча, чужого игрока, повреждённая и неоднозначная отклоняются без списания квоты; метод соответствия подтверждён GA-3 |
| FR-07 | Must | Асинхронный жизненный цикл | Пользователь видит загрузку, проверку, очередь, обработку, успех либо ошибку; каждая ошибка имеет понятную причину и разрешённый следующий шаг |
| FR-08 | Must | Идемпотентность | Повтор того же запроса/события не создаёт второе логическое задание, отчёт или списание. Повторный анализ другой версией модели — отдельное явное действие |
| FR-09 | Must | Статистика игры | На эталонных матчах агрегаты согласуются с исходными событиями по утверждённой методике; несовместимые метрики игр не смешиваются |
| FR-10 | Must | Отчёт по эпизодам | Эпизод содержит время/интервал, тип, объяснение по наблюдаемым данным и версию модели; если эпизодов нет, это сообщается без обещания отсутствия всех ошибок |
| FR-11 | Must | Бесплатная квота и демонстрационный Premium | Бесплатно допускаются три успешных анализа за утверждённый период. Конкурентные запросы не превышают лимит; ошибки освобождают резерв. Premium снимает только лимит количества, не ресурсные ограничения |
| FR-12 | Must | Приватность файлов и персональных отчётов | Чужой пользователь не получает исходную запись или персональный отчёт через подбор ID/URL. Публичный просмотр базовой статистики остаётся отдельным сценарием |
| FR-13 | Must | Управляемое хранение | По истечении настроенного срока исходный объект удаляется; метаданные отражают удаление. Политика результатов отдельная и опубликована |
| FR-14 | Should | Удобное обновление статуса | Интерфейс обновляет состояние без повторного создания задания; механизм polling/SSE выбирается отдельно |

Premier включён в FR-03 по явному решению пользователя от 19.10.2026. Практическая проверка пути получения карточек перенесена в GA-58 после первой сдачи 24 октября; до её завершения это обязательное требование с открытым техническим риском. Даже для FACEIT/OpenDota приёмка FR-05/06 зависит от доказанного сопоставления. Если оно невозможно, нельзя объявлять персональный анализ этого источника завершённым: требуется пересогласование охвата.

## Проектные нефункциональные требования

Все численные цели ниже предложены для обсуждения, ещё не измерены. До финальной приёмки зафиксировать конфигурацию CPU/RAM/диска, набор данных и сценарий нагрузки. Внешние API измерять отдельно от внутренних запросов.

| ID | Предлагаемая цель | Проверка |
|---|---|---|
| NFR-01 | p95 чтения закэшированного профиля/карточки ≤ 1 с при 20 одновременных пользователях в течение 5 минут; ошибки сервера < 1% | Нагрузочный отчёт с конфигурацией стенда и объёмом данных; внешние вызовы исключены и измерены отдельно |
| NFR-02 | После перезапуска одного worker задание не теряется; в тесте из 20 заданий все получают конечный статус, дубликатов списания нет | Интеграционный сценарий с прерыванием обработки и повторной доставкой |
| NFR-03 | Все защищённые операции проверяют аутентификацию и принадлежность ресурса | Негативные тесты без сессии и с другим пользователем для каждого защищённого endpoint |
| NFR-04 | Парсинг ограничен размером, временем, памятью и числом одновременных процессов | Тесты превышения каждого лимита; worker остаётся работоспособным |
| NFR-05 | По одному job_id можно проследить обработку через сервисы | Логи содержат correlation/job ID, метрики очереди и ошибок; токены и полные записи не логируются |
| NFR-06 | Описание публичного API и миграции воспроизводимы | Другой участник поднимает стенд по инструкции и выполняет основной сценарий |
| NFR-07 | Качество модели измерено отдельно для каждой игры и типа ошибки | Precision/recall/F1, число эпизодов, baseline, разбиение по матчам и правила временного совпадения опубликованы; пороги фиксируются в GA-52 до финального теста |

Срок обработки демки пока не обещается: сначала замер GA-3 на репрезентативных файлах. Затем установить бюджет по размеру/длительности записи и конфигурации worker.

## Решения, которые нужно согласовать

| Вопрос | Предложение для обсуждения | Кто подтверждает / основание |
|---|---|---|
| Период бесплатной квоты | 3 успешных анализа за календарный месяц UTC; остаток не переносится | Амир + команда; исходно период не выбран |
| Размер загрузки | Предварительно 1 GiB; окончательно после замеров GA-3 | Ерхан, с примерами обеих игр |
| Сжатые записи | Разрешать только проверенные форматы после GA-3; ограничивать распакованный объём и коэффициент расширения | Ерхан |
| Параллелизм | 1 активный анализ на пользователя; Premium имеет тот же технический предел | Команда после оценки ресурсов |
| Срок хранения | Предварительно 7 дней для исходной записи; результаты до удаления пользователем, с явно утверждённой политикой | Команда, с оценкой стоимости и требований |
| Видимость отчёта | Личный отчёт доступен владельцу; публичные общие показатели отдельно | Амир + команда |
| Premier | Обязателен в MVP; способ подключения истории и получения карточек ещё проверяется | Решение пользователя 19.10.2026; исследование GA-2, практическая проверка GA-58 после первой сдачи |
| Ошибки ML и объём выборки | Ограниченный согласованный набор типов по каждой игре | Қажмұрат, GA-4/GA-52 |

Для резервирования квоты предлагается атомарно учитывать успешные и активные задания текущего периода. Резерв закрепляется за периодом создания; при технической ошибке освобождается. Повторная обработка одного события не меняет учёт. Эти правила нужно утвердить вместе с периодом.

## Что вне обязательного MVP

Автоскачивание демок; реальные платежи и биллинг; matchmaking; новые игры; полная история любого Premier-игрока; открытый доступ к чужим исходным файлам; универсальный рейтинг навыка между играми. Будущие функции не должны скрыто становиться условиями основной приёмки.

## Трассировка и завершение задачи

- Доступность данных и поля: GA-2 → FR-01/02/03.
- Идентичность записи и ограничения парсера: GA-3 → FR-05/06, NFR-04.
- Методика ML: GA-4/GA-52 → FR-10, NFR-07.
- Интерфейс: GA-33 → сценарии FR-01–14.
- Архитектура и выбор технологий: GA-5/GA-51 → сервисные границы и NFR.

Для закрытия GA-1: заполнить открытые решения, согласовать охват и численные критерии, устранить расхождения с GA-2/GA-3, получить ревью другого участника и сохранить PR. Текущий документ — результат начала задачи 19 октября, не доказательство завершённой реализации.
