# GA-2 — источники данных и границы интеграций

Автор: Алимов Амир Сакенулы, SE-2431. Дата: 19 октября 2026.
Статус: FACEIT и OpenDota проверены на примерах; Steam/Premier требуют отдельного практического прогона. Не готово к закрытию.
Пользователь 19.10.2026 попросил пока отложить подключение для проверки Premier. Требование поддержки Premier в MVP сохраняется; задача остаётся в работе до возобновления этой проверки.
Задача: https://gameanalytics-se2431.youtrack.cloud/issue/GA-2

## Вывод для проекта

Решение пользователя от 19.10.2026: **Premier обязателен в MVP** наряду с CS2 FACEIT и Dota 2. Источники FACEIT и OpenDota проверены на реальных ответах; Premier остаётся обязательным, но технически не подтверждённым требованием. Его нельзя молча исключить или объявить работающим. Steam нужен для идентификации и профиля. Полная история произвольного Premier-игрока по одному публичному SteamID не подтверждена.

Выбранный продуктовый сценарий сохраняется: человек открывает существующую карточку матча и вручную загружает запись. Отдельной кнопки создания матча загрузкой файла нет. Следовательно, доступность карточки и проверка соответствия записи — обязательные условия включения источника в MVP.

## Матрица источников

| Источник | Документированный доступ и данные | Ограничения | Решение для проекта |
|---|---|---|---|
| Steam Web API | GetPlayerSummaries принимает ключ и SteamID, возвращает сведения профиля: имя, аватар, URL, состояние видимости [S1] | Метод профиля не является историей CS2. Полученный SteamID сам по себе не доказывает владение аккаунтом | Профиль и внешний идентификатор; подтверждение владения отдельным механизмом входа |
| OpenDota | Профиль `/players/{account_id}`, история `/players/{account_id}/matches`, последние матчи и детали `/matches/{match_id}`; account_id — Steam32 [S2] | Наличие endpoint не гарантирует полноту истории и детальной статистики каждого матча. Доступность конкретных полей, приватных игроков и актуальные квоты проверяются экспериментом | История и карточки Dota 2; отсутствующие данные показывать явно |
| FACEIT Data API | Ключ приложения и Bearer-аутентификация для публичных данных [S3]. История `/players/{player_id}/history`, карточка `/matches/{match_id}`, статистика `/matches/{match_id}/stats`. Схема содержит match_id, game, временные поля, команды, участников, faceit_url, demo_url [S4] | История FACEIT не покрывает Premier. Поля могут отсутствовать; идентификатор FACEIT нельзя напрямую считать идентификатором в демке | Карточки CS2 FACEIT после проверки ключа, реального матча и сопоставления с демкой |
| FACEIT Downloads API | Отдельно одобряемый доступ; resource_url обменивается на подписанный download_url [S5] | Data API key не равен разрешению на Downloads API. demo_url не следует считать общедоступной прямой ссылкой | Не подключать в обязательном MVP; пользователь скачивает запись через доступный ему интерфейс FACEIT |
| CS2 Premier | Valve описывает доступ к истории через game authentication code; в объявлении 2023 г. указан Premier и начальный share code не старше месяца [S6, S7] | Историческая документация не заменяет актуальный тест. Получение полной карточки из share code и работа с Game Coordinator ещё не проверены | Обязательная часть MVP по решению пользователя; GA-2 не закрывать до проверки пути получения карточек |

## Результаты практической проверки

### FACEIT — ответы предоставлены пользователем

Пользователь подтвердил `200 OK` для четырёх запросов: профиль, история, детали и статистика. Ключ остался у пользователя. Время выполнения запросов и HTTP-заголовки не предоставлены; это не прямой запуск агента.

- История содержит пять завершённых CS2-матчей; целевой игрок присутствует во всех составах.
- Матч `1-f9be9eb1-2728-45df-ac64-1c22e032652e` совпадает в истории, деталях и статистике: Dust2, 13:11, 24 раунда. Для целевого игрока: 31 убийство, 18 смертей, 9 ассистов, ADR 142.2, HS 65%.
- История содержит время, составы и результат, но не подробную индивидуальную статистику; она получена отдельным запросом `/matches/{match_id}/stats`.
- В статистике числа приходят строками: например `"Kills": "31"`. Требуется явное преобразование, при отсутствующем/невалидном значении — `null`, не ноль.
- История возвращает `finished`, детали — `FINISHED`: нормализовать регистр. Победитель в деталях — `faction1`, в статистике — ID команды; сопоставлять через данные команды.
- В истории `from=0`, получены матчи июля–августа. Не объявлять эту выдачу ограниченной последним месяцем; задавать период явно и проверять пагинацию отдельно. Полнота всей истории не проверена.
- Поле ресурса демки присутствует, расширение `.dem.zst`. Доступность скачивания не проверялась; автоскачивание не включается.
- SteamID из профиля/состава связывает публичные записи, но не доказывает владение аккаунтом вошедшим пользователем или соответствие загруженной демки.

Артефакт: [выбранные поля ответов FACEIT](evidence/faceit-observed.json). Это сокращённые данные, не неизменённый raw HTTP response; аватары, друзья и посторонние игровые имена исключены.

### OpenDota — прямые запросы без ключа

Шесть запросов выполнены 19.10.2026, все вернули `200`. Проверены пустая история выбранного аккаунта, список proMatches, профиль публичного игрока, его история из пяти матчей и детали матча из этой истории.

Матч `9052605658`: 10 участников, длительность 3377 секунд, победа Radiant, счёт 41:22. Фактически присутствуют `hero_id`, K/D/A, GPM, XPM, last hits, denies, урон героям/строениям и лечение. Поля objectives/teamfights присутствуют в этом матче; их наличие у всех матчей не доказано.

Для Steam32 `1181750437` получено `200 []`. Это означает отсутствие доступных записей в данной выдаче; причина (нет игр, приватность, неполный индекс) не установлена. Положительный пример выбран из участников профессионального матча, поэтому не доказывает полноту истории обычных игроков.

Артефакты: [выбранные поля](evidence/opendota-observed.json), [URL, время UTC и HTTP-статусы](evidence/opendota-request-log.json). Ранее наблюдавшаяся DNS-ошибка окружения устранена при повторном прогоне; это не текущий блокер.

### Steam и Premier — граница подтверждённого

Steam GetPlayerSummaries проверен по документации, но запрос с действующим ключом не выполнен. SteamID в ответе FACEIT не является проверкой Steam Web API.

Официальный публичный список методов `ISteamWebAPIUtil/GetSupportedAPIList/v1/` вернул `200`, но без интерфейса `ICSGOPlayers_730`. Это не доказывает отсутствие метода при авторизованном доступе. Страница Valve Developer Wiki о match history вернула 403 при чтении; актуальная схема по ней не подтверждена. Старые официальные объявления [S6, S7] подтверждают механизм подключения истории, а не успешную современную интеграцию.

План проверки Premier: подключённый Steam-аккаунт → разрешение истории и свежий share code → получение следующего кода → получение метаданных матча → создание карточки → ручная загрузка. Последовательность является исследуемым вариантом, а не реализованной функцией. Для проверки нужны локальные секреты и реальный недавний Premier-матч. Game Coordinator, его авторизация и доступные поля карточки остаются отдельным техническим риском.

Нельзя автоматически заменить этот сценарий ручным созданием карточки или загрузкой на отдельном экране: пользователь исключил кнопку «Добавить матч». Если проверка не даст надёжных метаданных, GA-2 остаётся незавершённой; изменение UX или объёма согласуется отдельно. Временное отсутствие карточек обозначается как неподключённый источник, а не отсутствие всех матчей игрока. Публичный просмотр возможен для уже доступных платформе данных; произвольная полная история всех Premier-игроков не обещается.

## Поля внутренней карточки: проектный контракт

Это требования нашего приложения, а не утверждение, что все источники возвращают все поля.

| Поле | Назначение | При отсутствии |
|---|---|---|
| `id`, `game`, `source`, `external_match_id` | Внутренний UUID; игра; источник; внешний ID как строка. Уникальность по `(source, game, external_match_id)` | Карточку не создавать без устойчивого внешнего ключа |
| `started_at`, `duration_seconds` | Время UTC и длительность | `null` и пометка «нет данных» |
| `participants` | Внешний ID игрока с namespace; SteamID64 — строка, если известен | Запрет персонального анализа без подтверждённого сопоставления |
| `result`, `map_or_mode`, `statistics` | Результат и игровые показатели | Показывать только доступное; не заменять пропуски нулями |
| `source_url`, `fetched_at` | Проверяемый источник карточки и время обновления | Не формировать произвольную ссылку из недоверенных входных данных |
| `analysis_available`, `unavailable_reason` | Возможность анализа и понятная причина отказа | Кнопка загрузки недоступна до проверки поддержки |

Общие показатели: число доступных матчей и доля побед на явно указанном наборе. Метрики, специфичные игре, хранить отдельно. K/D, GPM и другие разные величины не объединять в один «универсальный скилл» без отдельной обоснованной методики. Вместе с агрегатом показывать период, размер выборки и источник.

## Проверка загруженной записи — совместно с GA-3

1. Подтвердить Steam-аккаунт пользователя; введённый вручную SteamID не достаточен.
2. Проверить тип, размер и поддерживаемую версию записи; вычислить хеш на сервере.
3. Извлечь идентификаторы и состав игроков. Идентификатор Dota 2 и внешние FACEIT IDs проверять раздельно.
4. Использовать точный проверенный идентификатор матча, если он доступен. Если остаётся только сочетание времени, карты и состава, оценить неоднозначность на реальных записях. Совпадение имени файла или одной карты недопустимо.
5. Не запускать платный/лимитируемый анализ при чужом матче, чужом игроке или неоднозначном соответствии. Сообщить причину; квоту не списывать.

Если GA-3 не подтвердит надёжное сопоставление FACEIT-карточки и демки, для этого источника оставить просмотр статистики; анализ обозначить неподдерживаемым до решения. Это существенный риск обязательного анализа CS2, который нужно согласовать с руководителем, а не скрывать в документации.

## План воспроизводимой проверки

| Проверка | Что сохранить | Условие успеха | Состояние 19.10 |
|---|---|---|---|
| OpenDota: история и детали реального игрока | URL без секретов, время UTC, HTTP-статус, сокращённый JSON и список фактически непустых полей | По ID из истории получена карточка; наличие/отсутствие участников и статистики зафиксировано | Выполнено на публичном игроке; также проверена пустая история |
| FACEIT: поиск игрока, история CS2, match и stats | Сокращённые ответы пользователя, без Authorization | ID из истории совпадает с карточкой, проверены участники и статистика | Выполнено по предоставленным ответам; четыре HTTP 200 подтверждены пользователем |
| Steam: публичный/закрытый профиль | Два ответа без ключа и персональных избыточных полей | Реальная разница видимости отражена в UI-контракте | Не выполнено: ключ не предоставлен |
| Premier: возможность получить карточку | Официальные источники и реальный ответ | Воспроизводимый путь, совместимый с UX; Premier обязателен | Ожидает подключения тестового аккаунта и проверки метаданных |
| Демо: верная, чужая, другой матч, повтор | Вывод GA-3 и перечень проверяемых идентификаторов | Нет ложного принятия и двойного списания | Выполняет GA-3 |

Для повторения OpenDota использовать URL из журнала запросов. Проверка приватного профиля, границ пагинации, квот и отказов 429/5xx ещё не проводилась. Это ограничения эксперимента; успешные примеры не являются полноценным нагрузочным или интеграционным тестом приложения.

Ключи хранить локально в секретах окружения, не в Git, описании YouTrack или скриншотах. Перед сохранением ответа проверить состав персональных данных. Обработать 401/403 как проблему доступа, 429 как ограничение частоты, временные ошибки — ограниченными повторами. Конкретные квоты запросов закрепить после проверки текущего тарифа, не выдумывать.

## Что ещё нужно для закрытия GA-2

- Получить реальные ответы Steam с действующим ключом, включая поведение недоступного профиля.
- Проверить получение карточки Premier для подключённого игрока; Premier обязателен и не исключён из MVP.
- Зафиксировать способ подключения Premier и фактические ограничения. Коды авторизации в Git не сохранять.
- Провести ревью документа другим участником и приложить PR.

GA-3 остаётся зависимостью реализации персонального анализа, но не требует ждать завершения парсера, чтобы закончить исследование источников GA-2. Полное завершение GA-2 сейчас не заявляется из-за Steam/Premier, а не из-за незавершённого парсера.
