# GA-3 - проверка извлечения и идентификации матча по демкам

## Цель

Проверить, можно ли извлечь метаданные из демок CS2 и Dota 2 и надёжно сопоставить файл с выбранной карточкой матча и SteamID пользователя.

## Среда эксперимента

- Дата замеров: 21.10.2026. Windows `10.0.26200.9711` x64; PowerShell 7.6.
- CPU: AMD Ryzen 5 5600H with Radeon Graphics. Windows сообщает 13,86 GiB общего объёма физической памяти, доступной ОС; объём установленных модулей отдельно не проверялся.
- Clarity 5.0.1, Gradle 9.7.1, Eclipse Temurin JDK 21.0.12.1; команды `dev:userinfo` для CS2 и `examples:combatlog` для Dota 2.
- Для дополнительного извлечения состава CS2: Python 3.14.4, `demoparser2` 0.42.0. Распаковка: Zstandard CLI 1.5.7.
- Время и пиковая рабочая память процесса (Working Set) измерялись по трём запускам. Clarity JAR были собраны заранее и build в таймер не входил; время CS2 - длительность процесса Java, включая запуск JVM. Working Set опрашивался каждые 20 мс; это не жёсткий лимит памяти.
- Все исходные демки хранятся вне репозитория. В Git добавляются только краткие метаданные и результаты.

### Ограничения CS2

- Файлы относятся к FACEIT; выводы не распространяются автоматически на Premier или другие источники.
- По трём файлам подтверждено чтение Source 2 и извлечение карты, версии/сборки и времени воспроизведения.
- SteamID участников извлечены `demoparser2` и сверены с карточками всех трёх матчей. FACEIT match ID из байтов демки не извлечён: ID C взят из имени файла, затем запрошена карточка по этому ID и сверены карта и весь состав.
- В продукте имя файла нельзя считать достаточным доказательством: при отсутствии подтверждённого ID из содержимого следует сверять полный состав и доступные поля карточки; неоднозначное соответствие отклонять или отправлять на ручную проверку.
- Карта и приблизительное время пригодны как контрольные признаки, но сами по себе не гарантируют уникальную идентификацию.
- Для тестовой выборки замерены полный проход Clarity, извлечение состава `demoparser2`, распаковка и пиковая память. Это не гарантия для Premier, всех сборок игры и файлов около установленных лимитов.

## Ресурсы обработки

| Игра / демка | Сжатый -> распакованный размер, байт | Распаковка: время; пик zstd | Полный проход Clarity: время процесса; пик памяти |
|---|---:|---:|---:|
| CS2 A | 280 186 403 -> 379 767 737 | 0,55 с; 9,3 MiB | 1,40 с; 670,7 MiB |
| CS2 B | 224 381 123 -> 310 601 220 | 0,42 с; 9,9 MiB | 1,26 с; 603,1 MiB |
| CS2 C | 223 445 147 -> 304 341 794 | 0,40 с; 9,9 MiB | 1,24 с; 585,0 MiB |
| Dota 2 A | 84 250 915 -> 147 003 686 | 0,20 с; 11,4 MiB | 2,04 с; 386,2 MiB |
| Dota 2 B | 68 153 973 -> 120 467 068 | 0,16 с; 11,4 MiB | 1,82 с; 346,6 MiB |

Каждое время - медиана трёх прогонов; пик памяти - наибольшее наблюдение в этих прогонах. Распаковка выполнялась с записью во временный файл; временные копии удалены. JAR были собраны заранее, поэтому build не включён. Время процесса Clarity включает запуск JVM; измеренная рабочая память также включает запуск. Для последовательных этапов пики памяти не складываются.

Clarity CS2 проход выполнялся `dev:userinfo` и читал весь replay, но декодировал только часть состава: A - 1/10, B - 3/10, C - 4/10; служебный `DemoRecorder` с XUID `0` не считается игроком. Отдельно `demoparser2.parse_player_info()` извлёк по 10 участников. Медиана времени вызова - 2,069 с (A), 2,046 с (B), 2,088 с (C); пиковая рабочая память процесса - 472,9 / 428,6 / 474,3 MiB. Таймер Python начинался после импорта и создания парсера; память измерена для всего процесса. Это извлечение состава, не разбор игровых событий.

Clarity Dota проход выполнялся примером `combatlog`, который форматирует события боя; время включает обработку и логирование. Скачивание Dota (121,74 и 103,92 с) - отдельный сетевой этап и в таблицу обработки не входит.

### Оценка предварительных лимитов

Максимум выборки - 280 186 403 байта на входе и 379 767 737 байт после распаковки; обе величины ниже порогов 1 GiB и 2 GiB. Самый долгий измеренный цикл «распаковка + полный проход» - около 2,24 с, ниже лимита 15 минут. Максимальная наблюдавшаяся рабочая память - 670,7 MiB, ниже 2 GiB. Значит, пороги не нарушены на этих пяти файлах. Процесс не запускался под жёстким лимитом 2 GiB, а файлы не приближались к предельным размерам; значения остаются предварительными, не гарантией для всех демок и версий.

## Вывод

### Предварительное правило принятия файла

| Ситуация | Решение |
|---|---|
| В файле есть точный ID матча, он совпал с карточкой, SteamID пользователя найден среди участников | принять |
| Точный ID матча есть, но он отличается | отклонить |
| SteamID пользователя не входит в участников | отклонить как чужой файл |
| Точного ID нет, совпадают только карта, время или часть игроков | неоднозначно; автоматически не принимать |
| Файл повреждён или парсер не поддерживает его версию | отклонить с понятной причиной |

### Подтверждённые результаты

- **Dota 2:** в двух реплеях извлечены `match_id` и SteamID всех десяти игроков. Правильный матч совпал с карточкой; другой матч того же игрока отклоняется по ID.
- **CS2:** по A/B/C совпали карта и все 10 SteamID с соответствующими карточками; A и C - разные матчи Dust2, в C нет целевого игрока. FACEIT UUID не извлечён из байтов демки: для C ID взят из имени исходного файла и проверен запросом карточки, включая весь состав.
- **Ресурсы:** все пять файлов меньше предварительных лимитов размера; наблюдавшийся пик памяти Clarity не превысил 670,7 MiB, а измеренный цикл обработки был короче 2,24 с. Это подтверждает пригодность заданных порогов для минимальной тестовой выборки, но не заменяет стресс-тест под жёстким ограничением памяти.

### Что остаётся проверить

Не проверены повреждённые, пустые и неподдерживаемые файлы, а также поведение при жёстком лимите 2 GiB. Выборка невелика и не доказывает поддержку Premier или всех версий формата. Для CS2 внешний match ID не извлекается из содержимого в проверенном пути: до реализации нужно использовать проверенные метаданные карточки и полный состав; не полагаться только на имя файла, карту или одного участника.
