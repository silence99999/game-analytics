# GA-3 - проверка извлечения и идентификации матча по демкам

## Цель

Проверить, можно ли извлечь метаданные из демок CS2 и Dota 2 и надёжно сопоставить файл с выбранной карточкой матча и SteamID пользователя.

## Среда эксперимента

- Дата проверки: 20.10.2026.
- ОС: Windows 11, 10.0, amd64; PowerShell.
- Процессор и объём RAM: не зафиксированы.
- Парсер: примеры библиотеки Clarity из `skadistats/clarity-examples`; для CS2 запускались `headerRun` и `infoRun`. Версия Clarity не зафиксирована.
- Сборка: Gradle 9.7.1, Eclipse Temurin JDK 21. Пример `dumpRun` запускался для поиска SteamID, но выдавал полный поток бинарных сетевых сообщений; его вывод не использовался как результат, выполнение было прервано.
- Способ распаковки Dota 2: Python 3.14, модуль `compression.zstd`.
- CS2: Clarity успешно прочитал `.dem` файлы, скачанные как `.dem.zst`; детали распаковки и исходный размер архива отдельно не зафиксированы.
- Файлы демок и реплеев хранятся вне репозитория. В репозитории остаются только метаданные, хеши и результаты.

Следовательно, по текущему эксперименту пока нельзя утверждать, что Clarity не может извлечь SteamID; только что выбранные примеры этого не предоставили.

### Ограничения CS2

- Файлы относятся к FACEIT; выводы не распространяются автоматически на Premier или другие источники.
- По двум файлам подтверждено чтение формата Source 2 и извлечение карты, версии/сборки и времени воспроизведения.
- Совпадение SteamID с вошедшим пользователем и извлечение FACEIT match ID из тела демки пока не проверены.
- Карта и приблизительное время пригодны как контрольные признаки, но сами по себе не гарантируют уникальную идентификацию.
- Пиковая память и чистое время полного разбора не измерялись. Время распаковки измерено отдельно; времена `BUILD SUCCESSFUL` не считаются временем разбора.
- Фактический размер сжатого `.dem.zst` требует перепроверки: переданные значения для `.dem.zst` и `.dem` совпадают.

### Формат файла

- Valve отдаёт реплей по ссылке с расширением `.dem.bz2`, но содержимое сжато zstd, а не bzip2. Первые байты скачанного файла `28 B5 2F FD` (сигнатура zstd); `bz2.open` выдаёт `OSError: Invalid data stream`.
- После распаковки файл начинается с `PBDEMS2\x00`, то есть это Source 2 demo.
- Расширению нельзя доверять как единственному признаку формата; формат следует определять по сигнатуре.

## Вывод

### Предварительное правило принятия файла

| Ситуация | Решение |
|---|---|
| В файле есть точный ID матча, он совпал с карточкой, SteamID пользователя найден среди участников | принять |
| Точный ID матча есть, но он отличается | отклонить |
| SteamID пользователя не входит в участников | отклонить как чужой файл |
| Точного ID нет, совпадают только карта, время или часть игроков | неоднозначно; автоматически не принимать |
| Файл повреждён или парсер не поддерживает его версию | отклонить с понятной причиной |

### Подтверждённые результаты

- **Dota 2:** в проверенных реплеях извлечены точные `match_id` и SteamID всех десяти игроков. Правильный реплей совпал с карточкой; реплей другого матча того же игрока был отвергнут по `match_id`. Это подтверждает, что одной проверки SteamID пользователя недостаточно.
- **CS2:** Clarity прочитал обе FACEIT-демки; извлечённые карты `de_dust2` и `de_nuke` совпали с соответствующими карточками. При выборе A и загрузке B несовпадение видно по карте в этом наборе данных, хотя карта не является уникальным идентификатором. Точный FACEIT UUID и SteamID из использованных примеров не извлечены.
- **Обе игры:** измерения времени и памяти полного разбора пока неполны. Для Dota и CS2 есть успешное чтение файлов, но нет сопоставимого чистого benchmark полного парсинга и пикового использования памяти.

### Что остаётся проверить

Для завершения минимального эксперимента требуется подобрать безопасный способ извлечения SteamID/участников CS2 из демки либо явно указать ограничение и требуемые дополнительные метаданные. Также нужно повторно проверить размеры исходных CS2 `.dem.zst`, измерить время полного разбора и пиковую память, а для требования «несколько актуальных файлов обеих игр» по возможности добавить дополнительные реплеи. Текущие результаты не доказывают поддержку Premier или всех версий демок.
